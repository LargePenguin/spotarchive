# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Spotarchive is a cross-platform (Linux and Windows) Python CLI that caches metadata about a user's Spotify playlists into per-playlist `setlist.csv` files, then legally sources the songs through an abstracted download backend (default: [SomeDL](https://github.com/ChemistryGull/SomeDL), which pulls from YouTube/Deezer/etc.). YT Music support is planned. The full product spec is in `.tmp/spec.md`; the user-facing documentation lives in `docs/` (see **Documentation** below) — keep it in sync when behavior changes; `README.md` stays a short overview.

> [!IMPORTANT]
> **Privacy boundary — never cross it.** Never include personally identifying or sensitive information in source code, tests, documents (README, `docs/`, comments, fixtures, sample data), commit messages, or PR/changelist descriptions. This covers the computer hostname, usernames and home-directory paths, email addresses, IP/MAC addresses, secrets, API keys, passwords, session tokens, cookies, `x-bc` values, user agents captured from a real session, Spotify account/user IDs and real playlist contents. Use obvious placeholders (`<your-username>`, `example.com`, `dummy-token`) and fake data in tests and examples. Session/credential files must be gitignored and never committed. Before committing or opening a PR, review the diff and descriptions for such leaks.

## Commands

User install: `./install.sh` (Linux) or `install.ps1` (Windows), also usable as `curl ... | bash` / `irm ... | iex`. **Don't run either from a worktree** (they `pip install -e` into `.venv`; both refuse a worktree). Development setup, from the repo root with the virtualenv active:

```bash
pip install -e ".[dev,somedl]"          # package + pytest + SomeDL (default backend; also needs ffmpeg)
python -m playwright install chromium   # browser for the login (Chrome/Edge also work)
python -m pytest                        # all tests; browser tests skip if no browser is installed
python -m pytest tests/test_browser_auth.py   # real headless Chromium against a fake Spotify
```

Working CLI:

```bash
spotarchive                  # update check (asks first) -> login (if the saved one doesn't work) -> offer YouTube login (TTY, unless "don't ask again") -> fetch with selection -> download -> meta
spotarchive -l | --login [spotify|youtube]  # browser login helper; without a site it asks which (needs a TTY). Takes a value, so `-lf` is an error
spotarchive -l youtube --cookies FILE       # import the YouTube login from an exported Netscape cookies.txt instead (bare `-l` = youtube)
spotarchive -f | --fetch     # choose playlists and rebuild setlist.csv files; -fn / --fetch --noselect reuses previous selection
spotarchive -d | --download  # download missing songs of the selected, fetched setlists via the backend (-fd, -fnd combine)
spotarchive -t | --threads N # songs downloaded at once (default: [download] threads, 0 = half the CPU threads); 1 = backend's own output
spotarchive -m | --meta      # fix the tags of the songs that are there (-dm: meta still runs if some downloads failed)
spotarchive -c | --config FILE  # use another config file than spotarchive.toml in the project root
spotarchive -u | --update    # compare against __version__ on GitHub main and download the latest `main` over the install, no git needed (not combinable)
spotarchive -V | --version
spotarchive -h | --help
```

## Architecture

Package in `src/spotarchive/` (setuptools, `pyproject.toml`; console script `spotarchive = spotarchive.cli:main`). Dependencies: `playwright` (browser login), `requests`, `rich` (colors, progress bars), `questionary` (checkboxes, single-choice lists), `mutagen` (tags), `tomli` on Python 3.10; optional extra `somedl` (default backend, run as a separate program).

- **`cli.py`** — argparse flags and orchestration (`run_login(store, site, browser, cookies)` -> `run_spotify_login`/`run_youtube_login`/`import_youtube_cookies`, `ensure_login`, `offer_youtube_login`, `run_fetch`, `run_download`, `run_meta`); maps errors to exit codes (1 error, 130 cancelled). `main(argv, data_dir)` loads the config, and `data_dir` (when given) overrides its `data_dir` so tests can point it at a temp dir; `make_client`/`make_backend(settings)` and the module attrs `interactive_login`/`youtube_login` are the seams tests replace with fakes. `offer_youtube_login` (plain runs, after the Spotify login, only with a TTY, when there's no unexpired YouTube login and `offer_youtube_login` is true) asks yes / not now / don't ask again via `ui.choose_one`; a failed YouTube login only warns. `run_download` calls `backend.use_youtube_login(store.youtube)` when logged in (warns when it has expired). A successful YouTube login resets `offer_youtube_login` to true. With `-dm` (and plain runs) a download `CliError` is held until meta has run.
- **`config.py`** — `spotarchive.toml` (TOML, gitignored) in the project root (`parents[2]` of the module when that has `pyproject.toml`, i.e. a clone; else the CWD), or `--config`. Missing default file = defaults; unknown keys are errors. Keys: `data_dir` (relative to CWD), `[login] browser` (`chrome`/`edge`/`brave`/`vivaldi`/`opera`/`chromium`, normalized in `parse`; empty = auto-detect; used for the Spotify and the YouTube login window via `capture_login(browser=)` in `browser.py`, which errors rather than falls back when the named browser is missing; headless token refreshes are unaffected), `[download] backend`, `[download] threads` (0 = `default_threads()`, half of `os.cpu_count()`; `--threads` overrides), `[metadata] source` (`backend`/`setlist`), `[backends.<name>]` passed verbatim as `get_backend(name, **options)` kwargs minus `""` values (a bad kwarg → `ConfigError` in `make_backend`). `spotarchive.example.toml` (committed; the install scripts copy it if missing) must match the defaults: `tests/test_config.py` checks it. Tests never read a real config: the autouse `no_user_config` fixture in `conftest.py` repoints `config.default_path`.
- **`meta.py`** — metadata cleanup per selected, fetched playlist; files come from `find_present` (record + name match, like downloading). `source = "setlist"`: mutagen easy tags (title, artist list, album, date) from `setlist.csv`, saved only when different. `source = "backend"`: `backend.tag(song, file)` unless the record entry says it was tagged by this backend (`tagged`, or `backend` when `tags_downloads`); a backend without `can_tag` falls back to setlist. The record entry gets `"tagged": <backend name | "setlist">`.
- **`browser.py`** — the login window shared by all sites: `capture_login(site: LoginSite, profile_dir, ...)` -> `(cookies, user_agent)`. A `LoginSite` gives the login URL, which tab URLs count as logged in, a cookie filter, a login-cookie check and `watch_window`. Watched sites (Spotify) get a window with a DevTools port (below). Unwatched ones (YouTube) get **no port**, because any `--remote-debugging-port` sets `navigator.webdriver = true` and Google's sign-in refuses that as "not secure" in every browser: the user closes the window, then `open_headless_browser` starts the same executable headless (`--headless=new`, port, `about:blank`, same `--password-store=basic`) on the profile and the cookies are read over CDP. The browser decrypts its own store, which covers Windows app-bound encryption, and no YouTube page loads, so the cookies don't rotate. `login_browser(playwright, browser)` picks the window's browser: a `NAMED_BROWSERS` name (also found as a Flatpak on Linux, returned as `flatpak:<app id>` and started with `flatpak run`), else the first installed Chrome/Edge/bundled Chromium. Also `AuthError`, `LoginCancelled`, `BrowserUnavailable` (re-exported by `spotify/auth.py`). The CDP connect happens when the set of logged-in tab URLs changes, so a logged-out arrival (e.g. a consent page) doesn't block a later check.
- **`youtube/auth.py`** — YouTube login through `capture_login` (unwatched): Google `ServiceLogin?service=youtube` continuing to `www.youtube.com/signin`; done when the user has closed the window and the profile holds an unexpired `SAPISID`/`__Secure-3PAPISID`/`__Secure-1PAPISID` cookie (what yt-dlp authenticates with). `import_cookies(path)` (`--cookies`) is the fallback: parses a Netscape `cookies.txt` (`#HttpOnly_` prefix, `0` expiry = session cookie, BOM tolerated), keeps youtube.com cookies, `CookieFileError` without a login; the user agent stays empty. Keeps only youtube.com cookies + user agent; profile `data/browser-profile-youtube/`. No refresh and no requests to YouTube: `is_logged_in` only looks at cookie expiry.
- **`spotify/auth.py`** — Spotify browser login (window code in `browser.py`). `interactive_login` starts installed Chrome, then Edge, then Playwright's bundled Chromium as a **plain process** (not Playwright-driven: automated browsers get endless captchas on Spotify's login) on its own profile in `data/browser-profile/`, with `--remote-debugging-port=0` (port read from `DevToolsActivePort`). While the user logs in it only polls the DevTools HTTP `/json/list` for tab URLs; once a tab reaches `open.spotify.com` it connects over CDP, reads the `sp_dc` cookie and user agent, and closes the window with `Browser.close`, then gets the first token through `refresh_session`. It keeps only spotify.com cookies and the user agent. The login window gets no `--disable-blink-features=AutomationControlled` (current Chrome shows an "unsupported flag" banner for it, even though the DevTools port turns `navigator.webdriver` on); the headless launches keep that flag and also drop `--enable-automation`. `refresh_session` replays the cookies in headless Chromium to get a fresh token, so Spotify's token-endpoint signing (TOTP) is never reimplemented; from the same page load it reads the persisted-query hashes out of the main `web-player.*.js` script. `SessionTokenProvider` caches the token (and hashes) and refreshes it when it expires. (The spec mentions `x-bc`; that's not a Spotify header and isn't used.)
- **`spotify/client.py`** — read-only client for the web player's GraphQL API (`POST api-partner.spotify.com/pathfinder/v2/query`, persisted queries `profileAttributes`, `libraryV3` flattened with the `Playlists` filter, `fetchPlaylist`, `fetchLibraryTracks` for Liked Songs). The public Web API (`api.spotify.com`) is **not** used: it answers web-player tokens with 429. Only the bearer token is needed (no `client-token`). Offset pagination against `totalCount`, one forced token refresh on 401, one hash re-read (via token refresh) on 412 then `QueryOutdated`, `Retry-After` backoff on 429/5xx, `RateLimited` without waiting when Spotify asks for more than a minute. `DEFAULT_QUERY_HASHES` is the fallback when no hashes were captured.
- **`spotify/models.py`** — `Playlist`/`Track` parsed from pathfinder JSON. No ISRC in that API (the column stays, empty); Liked Songs have no album date. Liked Songs uses the pseudo ID `liked-songs` (`spotify:collection:tracks`).
- **`session.py`** — `data/session.json`: Spotify login (cookies, user agent, token + expiry, display name, query hashes), `youtube` (`YouTubeSession`: cookies in Playwright format, user agent, `logged_in_at_ms`; `netscape_cookies()` renders a yt-dlp `cookies.txt`), `offer_youtube_login` (missing keys load as `None`/`true`, so older files still work) and per-playlist state (`selected`, `folder`). Written atomically, mode 600 on POSIX.
- **`setlist.py`** — folder naming (Windows-safe, case-insensitive dedup by appending the playlist ID, previous owner keeps its folder, renamed playlists move their folder) and `setlist.csv` I/O. Columns: `name, artist, album, release_date, date_added, duration_ms, isrc, spotify_url`; artists joined with `; `.
- **`fetch.py`** — records the selection and writes setlists; one failing playlist doesn't stop the others.
- **`backends/`** — the download-backend interface. `base.py`: `DownloadBackend` (class attrs `name`, `shows_own_output`, `audio_extensions`, `can_tag`, `tags_downloads`; `check()` raises `BackendUnavailable`, `download(song, folder, events=None) -> list[Path]` raises `DownloadFailed` and may run in several threads at once, into the same folder; `DownloadEvents` carries `show_output` (false with several threads: stay quiet) and `progress`/`warning`/`error` callbacks; optional `warnings() -> list[str]`, `tag(song, file)` raising `TaggingFailed`, and `use_youtube_login(login)`, whose default stores it in `self.youtube_login`) and `Song` (a parsed setlist row; `key` = Spotify URL, else name/artists/album). `__init__.py`: `BACKENDS` registry + `get_backend(name, **options)`. Keep all helper-specific code in its own module; nothing outside `backends/` may know about SomeDL.
- **`backends/somedl.py`** — runs `somedl --here --skip-file-check [--format F] -- "First Artist - Title"` once per song via `Popen` with `cwd` = a `.somedl-download-*` staging folder inside the playlist folder; everything in it is moved into the playlist folder afterwards (keeps parallel downloads apart). SomeDL exits 0 even on failure, so success = an audio file in the staging folder. With `youtube_login` set, each run writes `netscape_cookies()` to its own `mkstemp` file (0600) passed as `--cookies` (before `extra_args`, so a user's own `--cookies` wins) and deletes it afterwards; yt-dlp writes rotated cookies back to that throwaway file, never to `session.json`. Output (stdout+stderr) goes through `OutputParser`: `label: WARNING|ERROR - msg` lines (wrapped lines joined, consecutive errors merged) -> events and the failure reason, `yt-dlp: Downloading NN%` from SomeDL's rich Live table -> progress. With `show_output` the raw bytes are also forwarded to our stdout (on a TTY SomeDL gets `FORCE_COLOR`/`TTY_COMPATIBLE` + the real size so it draws as usual; a Windows console without VT mode falls back to inherited stdio); without it, stdin is `DEVNULL` and SomeDL is forced into terminal mode with `COLUMNS=1000` so its table (the only source of the %) is drawn into the pipe. `--here` forces flat `{artist} - {song}` names regardless of the user's SomeDL config. Queries equal to SomeDL subcommands (`import`, `web`, ...) are refused. Option `flat=False` swaps `--here` for `--output .` (SomeDL's own template, subfolders). `tag()` drives the interactive `somedl import` wizard by piping answers to stdin (update mode, "file name is Artist - Song"; written against SomeDL 1.7 — recheck the prompt order in `SomeDL/core/extra.py` when bumping): the file is moved alone into a `.somedl-import-*` temp folder next to it, renamed to the setlist's `Artist - Song`, then moved back; success = its path in SomeDL's `somedl_import_cache`. Output is captured (shown only as the failure reason). Executable looked up next to `sys.executable`, then on PATH; `check()` also requires `ffmpeg`, and `warnings()` (non-fatal, printed before downloading) flags a missing `deno`, looked up next to `somedl` then on PATH like yt-dlp does. The `somedl` extra pulls in `yt-dlp[default,deno]` (Deno binary + challenge solver from PyPI): without a JS runtime YouTube streams often fail with HTTP 403.
- **`download.py`** — smart downloading. Per playlist folder, `.downloads.json` maps song key -> files (helpers name files after what *they* found, so names can't be matched reliably). A song is present if a recorded file exists or an audio file's stem matches `Artist - Song` (normalized; first/all artists; searched recursively, skipping dot-folders); name matches are written back to the record (`record_present`, which drops `backend`/`tagged` when the files changed). `prepare_playlist` works out the pending songs; `download_all(backend, playlists, threads, listener, log)` runs them sequentially (`threads=1`, `show_output=True`) or in a `ThreadPoolExecutor` shared by all playlists; records are only written from the calling thread, after each song; failures are collected, not recorded, and don't stop the rest. A `DownloadListener` (started/progress/warning/error from workers, finished from the caller) drives the display; `download_playlist` is the old single-playlist wrapper. Downloading only reads `session.json` + setlists, never Spotify.
- **`downloadlog.py`** — `DownloadLog`: `data/logs/download-<date>-<time>.log`, created with the first entry; every warning/error (per song, or general like the Deno warning) is appended and closed immediately, under a lock. In `cli.run_download` the display is `ui.DownloadBoard` for `threads > 1`, else the backend's own output (`shows_own_output`) or a progress bar; the run ends with per-playlist and total counts and the log path.
- **`install.sh` / `install.ps1`** (repo root) — single-command install. Use the checkout they sit in, otherwise download GitHub's `main` archive into `~/spotarchive` (`curl`/`wget` + `tar` on Linux, `Invoke-WebRequest` + `Expand-Archive` on Windows; over an existing install it just overwrites the repo files). No git needed. They create `.venv`, `pip install -e ".[somedl]"`, copy `spotarchive.example.toml` to `spotarchive.toml` if missing, run `playwright install chromium`, and install FFmpeg if it's missing, asking first (apt/dnf/pacman/zypper/apk with sudo; winget `Gyan.FFmpeg`). Then they ask whether to expose the command (`-y`/`-Yes` accepts, `--no-link`/`-NoLink` skips the question, no TTY skips it): a symlink in `~/.local/bin` on Linux, or a `spotarchive.cmd` launcher in `%LOCALAPPDATA%\spotarchive\bin` added to the user PATH on Windows (not `.venv\Scripts`, which would shadow python/pip). Idempotent; the options are documented in `docs/quickstart.md`. `install.ps1` must not call `exit`, since that closes the window under `iex`. Keep the two scripts' behavior and options in sync.
- **`update.py`** — self-update. `latest_version` reads `__version__` from `src/spotarchive/__init__.py` on GitHub `main` (raw.githubusercontent.com); versions compare by their numeric parts. Only an editable checkout can update itself (`project_root`: the directory around the imported package with `pyproject.toml`; worktrees are refused). `install_update` downloads GitHub's `main` zip (`ARCHIVE_URL`), writes each file over the checkout's (user files like `spotarchive.toml` and `data/` aren't in the repo, so they stay; files deleted upstream are left behind; zip-slip paths are refused) and reinstalls (`pip install -e` with the installed extras kept) only if `pyproject.toml` changed; on Windows the running `spotarchive.exe` is first renamed to `.exe.old` (`_move_launcher_aside`, restored if pip fails) because pip can't overwrite a running executable (WinError 32). No git involved. In `cli.py`, plain runs call `check_for_update` (never fatal; asks via `ui.confirm`, never updates without a TTY) and then `relaunch` the new code as `python -m spotarchive` with `SPOTARCHIVE_NO_UPDATE_CHECK=1`, which also lets users skip the check. **Users only get an update when `__version__` is bumped**, so the maintainer bumps it when a release should reach them; agents must never change it (see **Conventions**). Tests fake `latest_version` in an autouse fixture in `tests/conftest.py`; `test_update.py` fakes the archive download with in-memory zips.
- **`ui.py`** — rich console output: `ok` ✔, `error` ✘, `warn` `!`, `info` `::`, and `working(msg)`, a transient spinner (the board's) for slow steps — login, saved-login check, loading playlists, update check; without a terminal it prints `info` lines instead. ✔/✘/spinner fall back to `+`/`x`/`-\|/` on legacy Windows consoles (`_symbols()`, shared with the board). Don't wrap steps whose subprocesses write to the terminal (e.g. pip in `install_update`) in a spinner. Also questionary checkbox, progress bars, and `DownloadBoard` (docker-style: a spinner line per running song plus a bar under it while the progress is known, replaced by a ✔/✘ line with `counts()` "X downloaded; Y errors; Z warnings" once done; ASCII fallbacks on legacy consoles).

Everything must work on both Linux and Windows: use `pathlib`, avoid shell-specific assumptions, and don't hardcode path separators.

## Tests

pytest, in `tests/` (commands under **Commands**). Tests must never hit Spotify or download real audio — fake the Spotify layer and the download backend. `tests/conftest.py` has `FakeHttp` (queued responses per pathfinder operation name; an unknown operation gets 412), `FakeTokens` (with swappable query hashes) and builders for pathfinder JSON; `tests/test_cli.py` swaps `cli.make_client`, `cli.make_backend`, `cli.interactive_login`, `cli.youtube_login`, `ui.choose_playlists`, and `ui.can_prompt`/`ui.choose_one` for the prompts. `FakeBackend` (conftest) writes `SILENT_MP3` (a few silent MPEG frames mutagen can tag) and can report `song_warnings`, records `events.show_output` in `shown` and can fake `tag`; the autouse `one_thread_by_default` fixture pins `config.default_threads` to 1 so downloads run in order unless a test passes `-t`. `tests/test_somedl.py` fakes `subprocess.Popen` (with canned SomeDL output) and `subprocess.run`, including a fake `somedl import` that reads the piped answers. `tests/test_browser_auth.py` drives real headless Chromium but routes every request to fake Spotify pages (and aborts anything else) through the `configure_context` hook of `interactive_login`/`refresh_session`; the login window is replaced via `open_browser` by a fake user in a headless browser with a DevTools port, run from a separate thread, who "logs in" and gets redirected to the web player (or, for YouTube, in a window without a DevTools port, through a fake `/signin` page that sets `SAPISID` to `www.youtube.com`, then closes the window so the real headless reader opens the profile). Use only obviously fake data (`dummy-token`, `Fake Artist`).

## Conventions

Follow [Conventional Commits](https://www.conventionalcommits.org/) for commits, branch names and PR titles. Work is done on branches and merged via PR.

- **Types:** `feat` (new user-facing behavior), `fix` (bug fix), `docs` (README/`docs/`/CLAUDE.md/comments only), `refactor` (no behavior change), `perf`, `test`, `build` (dependencies, install scripts), `chore` (anything else). Pick the type for the change's main effect; split unrelated changes into separate commits.
- **Scope:** the feature area, lowercase, e.g. `auth`, `fetch`, `setlist`, `download`, `backend`, `somedl`, `meta`, `config`, `cli`, `ui`, `update`, `setup`. Reuse scopes already in `git log` rather than inventing near-duplicates.
- **Commit messages:** `type(scope): summary` — imperative mood, lowercase after the colon, no trailing period, subject ≤ 72 characters, e.g. `feat(fetch): add --noselect flag`. Use the body to explain *why* when it isn't obvious. Breaking changes (config format, setlist/session file layout, CLI flags) get `!` after the scope (`feat(config)!: ...`) and a `BREAKING CHANGE:` footer.
- **Branch names:** `type/scope-short-description`, lowercase kebab-case, e.g. `feat/fetch-noselect-flag`, `fix/setlist-date-parsing`, `docs/readme-badges`. `EnterWorktree` creates branches named `worktree-<name>`; right after entering, rename it with `git branch -m <conventional-name>` before the first push.
- **PR titles:** the same `type(scope): summary` form as a commit; for a single-commit PR, reuse its subject. The title is what lands in the merge history, so it should describe the whole PR.
- **PR bodies:** a short summary of what changed and why, then how it was tested (tests run, manual checks). Call out breaking changes, format migrations and documentation updates.

**Version number:** never change `__version__` (in `src/spotarchive/__init__.py`) or any other version number (e.g. in `pyproject.toml`) unless the user explicitly instructs you to. Don't bump it on your own even for changes that should reach users via `--update`; mention in the PR that a bump may be needed instead.

**Worktrees:** in a git worktree (e.g. under `.claude/worktrees/`), give it its own virtualenv — from the worktree root: `python3 -m venv .venv && .venv/bin/pip install -e ".[dev,somedl]"` (`.venv\Scripts\` on Windows). **Never symlink the project root's `.venv` into a worktree:** the user couldn't test the worktree's code, because the shared virtualenv's editable `spotarchive` points at the main checkout. A worktree's own `.venv` is safe to `pip install -e` into (it only repoints that venv), but **never run `pip install -e .` (or `pip install .`) with the project root's `.venv` active**, since it would repoint the user's `spotarchive` command at the worktree and break it once the worktree is removed. `.venv` is gitignored. Tests also work without the install (`pythonpath = ["src"]` in `pyproject.toml` makes pytest import the worktree's code).

**Finishing a task:** a task isn't done until it's in a PR. Commit on your branch, push it, and open a PR against `main` with `gh pr create` (title and body as above). Never push to `main` directly or merge the PR yourself.

**Merge conflicts:** before opening the PR (and again if `main` moves while it's open), `git fetch origin` and merge `origin/main` into your branch. Resolve any conflicts so both your change and the incoming work are kept — don't just take one side — re-run the tests, commit the merge and push. Confirm with `gh pr view --json mergeable` that the PR reports `MERGEABLE`; if it's `CONFLICTING`, repeat. Other agents may work in parallel worktrees, so expect `main` to have moved, especially in shared files like `CLAUDE.md` and `README.md`.
